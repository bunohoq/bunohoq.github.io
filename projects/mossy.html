Overview

배송 데이터 기반 탄소 배출량을 실시간 계산하고, 수수료의 최대 50%를 환경단체에 자동 기부하는 MSA 기반 소셜 임팩트 이커머스 플랫폼. 9개 마이크로서비스와 2개 공통 모듈에 Hexagonal Architecture · DDD · Event-Driven Architecture를 적용했습니다.

Key implementations

01
API Gateway — JWT 인증 필터 / 헤더 변환
Authorization 헤더 Bearer 토큰 추출 → JWT 파싱 → 내부 서비스 전달용 X-User-Id / X-Seller-Id / X-User-Role 헤더로 변환. GlobalCors 우선순위 적용으로 AWS 환경 Preflight 정상 동작 확보.
02
Lua Script CAS 기반 Refresh Token Rotation
Redis GET/SET 사이의 Race Condition을 단일 원자 명령으로 처리. RT 불일치 시 Replay Attack으로 판단하여 즉시 무효화 (반환값 1 / 0 / -1).
03
Saga 패턴 — 분산 트랜잭션 보상
소셜 로그인 토큰 발급 실패 시 rollbackSocialLogin() 호출로 Member 서비스 데이터 롤백. MSA 환경에서 최종 일관성(Eventual Consistency) 보장.
04
Transactional Outbox + Kafka 이벤트 순서 보장
@TransactionalEventListener(AFTER_COMMIT) 으로 DB 커밋 후 Kafka 발행 — 수신 서비스에서 항상 회원 데이터가 존재하도록 정합성 확보.

Troubleshooting

01 · Lua Script로 Refresh Token Race Condition 해결
문제동시 다발적 토큰 재발급 요청 시 Redis GET → SET 사이 Race Condition으로 동일 RT 중복 재발급 위험
원인GET과 SET이 별도 명령 → 원자성 미보장
해결Lua Script CAS 로직으로 단일 원자 명령 처리. 토큰 불일치 시 Replay Attack으로 즉시 무효화
결과재발급 구간 원자성 확보, 토큰 탈취·재사용 시나리오 방어
02 · Saga 패턴 — 분산 트랜잭션 정합성
문제Member 회원 생성 성공 후 Auth 토큰 발급 실패 시 고아 데이터 발생
원인MSA 환경 — 서비스 간 트랜잭션 경계 분리로 단일 롤백 불가
해결Saga 보상 트랜잭션 — 실패 시 rollbackSocialLogin(userId) 호출로 Member 데이터 삭제
결과고아 데이터 미발생, Eventual Consistency 보장
03 · Gateway CORS Preflight 차단 문제
문제AWS 배포 환경에서 브라우저 Preflight(OPTIONS) 요청이 Auth Filter에서 차단되어 CORS 오류 발생
원인Filter Chain 처리 순서상 GlobalCors 설정 전에 Auth Filter가 먼저 실행
해결GlobalCors 설정을 최우선 순위로 적용, OPTIONS 요청이 Auth Filter 우회
결과로컬·AWS 환경 모두에서 CORS 정상 동작
04 · TransactionalEventListener + Kafka 이벤트 순서
문제회원가입 트랜잭션 커밋 전 Kafka 발행 시 수신 서비스에서 회원 데이터 미존재 가능성
원인Spring Event와 Kafka 발행 시점이 트랜잭션 커밋과 분리되지 않음
해결@TransactionalEventListener(AFTER_COMMIT) 으로 DB 커밋 후 Kafka 이벤트 발행
결과DB 커밋 → Kafka 발행 순서 보장, 수신 서비스 데이터 일관성 확보
