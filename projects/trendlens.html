Overview

무신사 랭킹만으로는 "진짜 트렌드"를 포착할 수 없다는 문제 인식에서 출발. 내부 랭킹 데이터와 외부 검색 트래픽(네이버 DataLab)을 결합해 TrendScore를 산출하고, Gemini AI가 "왜 이 아이템이 주목받는지"를 자연어로 해석합니다.

Pipeline highlights

01
TrendScore 계산 엔진
단어 빈도(ScoreA)와 DataLab 검색 트래픽(ScoreB)의 편차를 정규화로 해결. FinalScore = A·0.4 + B·0.6, 전일 대비 growthRate로 HOT 판별.
02
크롤링 속도 5분 → 20–30초
20 키워드 × 10 블로그 순차 크롤링을 parallelStream() 으로 병렬 처리, 개별 URL try-catch 격리 — 약 10배 단축.
03
3단계 Fallback 크롤러
동적 크롤링 → Jsoup DOM 파싱 → 키워드 기반 카테고리 보정. User-Agent 변경 + AutomationControlled 비활성으로 봇 차단 회피.
04
AI 분석 — Gemini 프롬프트 엔지니어링
"요약(3줄) ||| 스타일링 팁(1문장)" 구분자 형식으로 출력 강제 → UI 파싱 안정성 확보. 분석 근거 sourceUrls 저장으로 출처 추적 가능.

Troubleshooting — 6 cases

01 · Selenium 크롤링 차단 & 요소 탐지 실패
문제Next.js 기반 무신사 페이지에서 CSR + Lazy Loading + 봇 차단(403)으로 상품 정보 수집 실패
해결UA 변경, disable-blink-features=AutomationControlled, WebDriverWait + JsExecutor. 3단계 Fallback(동적 → Jsoup → 키워드 보정)
결과봇 차단 감소, Lazy Loading 요소 안정 로딩, 데이터 누락 해소
02 · 데이터 수집 속도 저하 (5분 → 20–30초)
문제20 키워드 × 10 블로그 순차 크롤링으로 전체 파이프라인 5분 이상 소요
원인네트워크 I/O(Jsoup)가 이중 for-loop 안에서 Blocking 방식으로 동작
해결상세 페이지 크롤링을 parallelStream() 으로 병렬화, URL 단위 try-catch 격리
결과전체 실행 시간 약 10배 단축 (5분 → 20–30초)
03 · TrendScore ScoreB 미산출 & DataLab 연동 실패
문제로그상 "저장 완료"인데 TrendMetric 테이블 비어 있고 ScoreB가 항상 0
원인상품명(옵션·색상·특수문자 포함) 그대로 전송 → data: [] 빈 응답. HTTP 200만 체크하여 오판
해결검색어 전처리 후 순수 키워드만 요청. 빈 응답 시 Warning 로그 후 저장 스킵
결과TrendMetric 정상 적재, 의미 있는 랭킹 동작
Evidence · ScoreB 컬럼이 전부 0으로 적재된 실측 로그
04 · JPA Session/EntityManager is closed
문제크롤링 중 예외 한 번 발생 후 모든 DB 접근이 Session is closed 로 실패
원인큰 @Transactional 내부 RuntimeException → 영속성 컨텍스트 종료
해결대규모 메서드 트랜잭션 제거, 저장 로직만 REQUIRES_NEW 단위로 분리
결과장시간 크롤링에서도 세션 안정 유지, 단일 실패가 전체 배치를 중단시키지 않도록 격리
05 · Midnight Gap — 자정~배치 전 랭킹 공백
문제매일 자정~새벽 3시 사이 랭킹 페이지가 완전히 비어 보이는 현상
원인LocalDate.now() 기준 조회인데 배치 실행(03:00) 전에는 해당 날짜 데이터 없음
해결SELECT MAX(base_date) 로 DB에 존재하는 최신 날짜 조회 후 랭킹 반환
결과언제 접속해도 공백 없이 직전 배치 결과 노출
Evidence · 새벽 시간대 END OF LIST 빈 화면
06 · AWS 서버 타임존 불일치로 배치 미실행
문제새벽 3시 실행돼야 할 배치가 의도한 시간에 동작하지 않음
원인AWS 서버 기본 타임존이 UTC — @Scheduled(cron = "0 0 3 * * *") 가 UTC 03:00에 실행
해결zone = "Asia/Seoul" 명시로 스케줄러 타임존 고정
결과로컬·AWS 모두에서 KST 새벽 3시에 정확히 배치 수행
